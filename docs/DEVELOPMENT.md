# Разработчикам

Локальная расшифровка аудио и видео с фокусом на русский язык: словарь терминов, справочник «Кто есть кто»,
распознавание голосов, автопополнение справочников, очищенная расшифровка по спикерам, протокол по шаблону
и фоновая обработка папок. Всё работает на компьютере пользователя. LLM — встроенная (llama.cpp внутри
приложения, Metal на Mac) или внешняя через OpenAI-совместимый API (Ollama, LM Studio, свой сервер).

## Сборка

Нужны [Node.js](https://nodejs.org) с [pnpm](https://pnpm.io), [Rust](https://rustup.rs) и FFmpeg
(`brew install ffmpeg`); на Mac — ещё Xcode Command Line Tools.

```bash
pnpm install
pnpm tauri dev                      # приложение в режиме разработки
pnpm tauri build --bundles app      # сборка .app
```

FFmpeg приложение ищет рядом со своим исполняемым файлом, затем в системе. В поставку он не входит.

Уведомления на macOS работают только в собранном `.app` (`pnpm tauri build --debug --bundles app`),
в `tauri dev` их нет. Разрешение система спрашивает при первом запуске.

Nemotron 3 работает через библиотеку NeMo-Speech.cpp (NVIDIA). Готовых сборок с этой моделью пока нет —
она собирается из исходников (≈3 мин, нужны `brew install cmake ninja`); без неё движок в настройках не показан:

```bash
src-tauri/scripts/build-nemo-speech.sh
pnpm tauri build --bundles app --config src-tauri/tauri.nemotron.conf.json   # .app с библиотекой внутри
```

Данные: `~/Library/Application Support/app.ultratranscript/` (библиотека, модели, шаблоны).

## Проверка

```bash
pnpm check                          # типы интерфейса
cd src-tauri && cargo test --lib    # тесты ядра
```

Конвейер без интерфейса:

```bash
cd src-tauri && cargo run --release --bin ut -- запись.m4a [--protocol] [--whisper] [--lang en] \
  [--diar off|pyannote3|community1|nemotron3] [--threshold 0.6] [--llm gigachat-lightning] [--raw] [--live]
```

`--live` печатает то же, что видит окно: текст по мере распознавания и протокол по мере написания.
У CLI своя библиотека во временной папке (`UT_DATA_DIR`), модели — общие с приложением.

Интерфейс без ядра — на выдуманных данных (`src/lib/dev/mock.ts`): расшифровка и протокол «идут» в
реальном времени, модели «скачиваются».

```bash
pnpm dev            # http://localhost:1420 в обычном браузере
pnpm build:demo     # то же одним файлом: demo/index.html открывается прямо с диска
```

`demo/index.html?fresh` — первый запуск: модели не скачаны, библиотека пуста.

## Архитектура

```
Окно (Svelte, src/) ──invoke/events──► Ядро (Rust, src-tauri/src/)
                                         service.rs   очередь задач, фоновый обработчик, опрос папок, события
                                         pipeline.rs  Ingest → Enhance → ASR → Diarize → Identify → Correct → Enrich → Export
                                         audio.rs     предобработка для распознавания: шумоподавление DPDFNet, выравнивание громкости
                                         speech.rs    sherpa-onnx: GigaAM v3 | Whisper large-v3-turbo, Silero VAD, WeSpeaker
                                         diar/        диаризация: pyannote 3.0 | pyannote community-1 | Nemotron 3 | выключена
                                         llm.rs       LLM: встроенная (local_llm.rs, llama.cpp) или OpenAI-совместимый API
                                         markdown.rs  расшифровка и протокол в Markdown — основной формат выгрузки
                                         docx.rs      движок .docx-шаблонов: документ Word собирается по запросу
                                         store.rs     SQLite: библиотека, папки, архив, справочники; голосовые отпечатки (AES-256-GCM)
                                         voices.rs    образцы голоса: фрагменты для прослушивания, загрузка из файла
                                         exchange.rs  импорт и экспорт справочников: .xlsx, .csv
                                         media.rs     ffmpeg: любые форматы → 16 кГц; архив в Opus
                                         lang.rs      язык строк ядра: этапы, уведомления, ошибки
                                         tray.rs, notify.rs, appmenu.rs   значок в строке меню, уведомления, меню приложения
```

Окно: `src/lib/App.svelte` — каркас, `Sidebar` — библиотека с папками и архивом, `Recording` — запись
(`LivePane` — расшифровка в реальном времени, `ProtocolView` — протокол), `Welcome` — главный экран,
`settings/` — разделы настроек, `ui/` — общие элементы (меню, диалоги, сообщения, выключатель…),
`locales/` — строки на русском и английском, `state.svelte.ts` — общее состояние.

- Каноническая модель — `transcript.json` (`transcript.rs`). Очищенный текст, Markdown, .docx и протокол —
  её представления.
- **Выгрузка.** `transcript.md` и `protocol.md` пишутся в папку записи при каждой правке. Документ Word
  собирается по шаблону, когда пользователь выбирает «Экспорт» (или по правилу папки, если в нём включено
  «Сохранять также в Word»).
- **Шаблоны .docx** редактируются в Word. Метки: `{{поле}}`; `{{список}}` в пункте списка повторяется для
  каждого элемента; `{{таблица.колонка}}` в строке таблицы повторяет строку. **Набор меток шаблона = схема
  для LLM**: добавили в шаблон `{{риски}}` — LLM заполнит и это поле. Стандартных шаблонов два набора —
  русский и английский; какой взять, решает язык записи. В шаблоне расшифровки работают и русские,
  и английские метки (`{{реплики.текст}}` и `{{utterances.text}}`).
- **Реальное время.** Кроме событий `job` (этап и доля выполнения) ядро шлёт события `live`: распознанный
  фрагмент (`text`), сохранённый черновик расшифровки (`draft`: после разделения по спикерам и после каждой
  пачки редактуры) и куски протокола (`protocol`: JSON, как его пишет LLM; окно разбирает недописанный
  JSON — `parsePartialJson`). Всё показанное ядро помнит (`live`), поэтому окно, открытое посреди
  обработки, начинает не с пустого места.
- **Состояние записи** в базе — это состояние её расшифровки: по нему прерванная расшифровка продолжается
  после перезапуска. Протокол виден по событиям; пересборка файлов после правки событий не шлёт.
- **Язык.** Интерфейс переводится в окне (`src/lib/locales`). Строки, которые рождаются в ядре, — этапы,
  уведомления, меню, ошибки — переводит `lang::tr`. С LLM ядро говорит на языке записи: по-русски для
  русских записей, по-английски для остальных (с просьбой отвечать на языке расшифровки).
- Находки LLM сразу попадают в «Словарь» и «Кто есть кто» с пометкой «на проверке» (в меню — янтарный
  счётчик) и не влияют на текст, пока их не подтвердят; отклонённые повторно не предлагаются.
- Справочники импортируются и выгружаются в .xlsx и .csv (UTF-8 с BOM, разделитель «;»); при импорте
  столбцы узнаются по заголовкам, совпадающие записи дополняются. Голоса в файлы не попадают.
- Модели скачиваются внутри приложения при первом запуске (~214 МБ с GigaAM) и не входят в поставку:
  см. [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

## Распознавание

Модель выбирается в настройках, а для отдельной записи — через «Расшифровать заново»:

- **GigaAM v3** (по умолчанию) — для русского точнее и примерно в 7 раз быстрее, сама ставит пунктуацию;
- **Whisper large-v3-turbo** (+563 МБ) — многоязычная; язык записей задаётся в настройках или определяется
  автоматически. Таймкоды слов оцениваются внутри фрагмента, известные «галлюцинации» на тишине
  («Субтитры сделал…», «Thanks for watching») отбрасываются.

## Разделение по спикерам

| Движок | Как устроен | Скорость, M1 Pro | |
|---|---|---|---|
| pyannote 3.0 (по умолчанию) | sherpa-onnx: сегментация, WeSpeaker, иерархическая кластеризация с порогом | несколько минут на час | число спикеров зависит от порога («Настройки → Для разработчиков») |
| pyannote community-1 (+27 МБ) | pyannote.audio 4.0 на ONNX Runtime из sherpa-onnx: отпечатки по маске спикера, кластеризация VBx с PLDA | несколько минут на час | число спикеров находит сама |
| Nemotron 3 (+107 МБ) | NVIDIA, одна сеть сразу выдаёт спикеров (до 8); NeMo-Speech.cpp на Metal | ≈ 30 с на час | нужна библиотека, см. «Сборка» |
| Без разделения | вся запись — один спикер | — | диктовки, лекции |

community-1 сверена с pyannote.audio 4.0.7 на тех же входах: разметка совпадает (DER 0–0,4 %).
Шаг окна — 2 с вместо 1 с в pyannote: вдвое быстрее; при 2,5 с на коротких записях терялись спикеры.

## Предобработка звука

Перед распознаванием запись очищается от шума (стук клавиатуры, гул, вентилятор — нейросеть DPDFNet, 9 МБ)
и выравнивается по громкости: тихие и далёкие голоса поднимаются до общего уровня (до +30 дБ), громкие
опускаются. Обработанный звук идёт только в поиск речи и распознавание; диаризация, отпечатки голоса и плеер
работают с исходным: после шумоподавления отпечатки смещаются, и диаризация дробит людей на лишних спикеров.
Оба шага выключаются в настройках («Звук»), в CLI — флагом `--raw`.

WER на фразах FLEURS (ru) с эталонным текстом, GigaAM v3, шум — записи клавиатуры из ESC-50:

| Запись | Без обработки | Шумоподавление + выравнивание |
|---|---|---|
| Чистая | 7,9 % | 5,3 % |
| Стук клавиатуры, сигнал/шум 0 дБ | 30,3 % | 20,9 % |
| Спикеры тише на 0…24 дБ | 9,6 % | 7,0 % |
| Тихие спикеры + клавиатура | 60,4 % | 35,0 % |

## Встроенные LLM

| Модель | Размер | Лицензия | |
|---|---|---|---|
| GigaChat 3.1 Lightning (Сбер) | 6,5 ГБ | MIT | по умолчанию: русский «родной», MoE — быстрая |
| T-lite 2.1 (Т-Банк) | 5,0 ГБ | Apache 2.0 | Qwen3-8B, дообученная на русском |
| YandexGPT-5 Lite 8B | 4,9 ГБ | лицензия Яндекса | ограничения на коммерческое использование |
| Qwen3 4B Instruct | 2,5 ГБ | Apache 2.0 | для компьютеров с 8 ГБ памяти |

Ответ модели ограничен грамматикой из JSON Schema (для протокола схема строится из меток шаблона),
поэтому структура соблюдается даже маленькими моделями. Модели выгружаются из памяти через 5 минут простоя.
